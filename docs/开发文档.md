# CatchHot 开发文档

> 本文档记录已完成的功能、架构说明、使用方式与下一步计划。按 AGENT.md 要求持续更新。

## 1. 技术选型（已确认）

| 层次   | 选型                               | 说明                                       |
| ------ | ---------------------------------- | ------------------------------------------ |
| 后端   | Python 3.10 + FastAPI              | 异步框架，爬虫生态成熟                     |
| ORM    | SQLAlchemy 2.x（同步）             | 声明式模型                                 |
| 数据库 | MySQL 5.7（内网共享）           | 多用户共享同一数据源，无账号隔离         |
| 调度   | APScheduler 3.x AsyncIOScheduler   | 锁定 3.x 稳定 API（4.x 为全新接口不采用）  |
| 抓取   | httpx（异步）+ BeautifulSoup4/lxml | 接口类用 httpx，页面类用 BS4               |
| 前端   | Vue 3.5 + Element Plus + ECharts   | Vite 5 构建，开发时代理 /api 到后端        |
| 测试   | pytest + FastAPI TestClient        | 内存 SQLite 隔离，当前覆盖 18 个自动化测试 |

## 3. 启动方式

```powershell
# 后端（默认连接内网 MySQL，可通过环境变量覆盖）
pip install -r requirements.txt
python -m uvicorn backend.app.main:app --reload --port 8000

# 可选：自定义 MySQL 连接
# $env:CATCHHOT_MYSQL_HOST="10.25.101.149"
# $env:CATCHHOT_MYSQL_PASSWORD="your-password"

# 后端 Docker 启动
docker build -t catchhot-backend .
docker run --rm -p 8000:8000 catchhot-backend

# 前端（另开终端）
cd frontend
npm install
npm run dev        # 端口 5173，/api 自动代理到 8000

# 后端测试
python -m pytest
```

- 前端页面：http://localhost:5173
- 后端 API 文档：http://127.0.0.1:8000/docs

### 3.1 MySQL 配置

| 环境变量 | 默认值 | 说明 |
| -------- | ------ | ---- |
| `CATCHHOT_DATABASE_URL` | （由下方参数拼接） | 完整连接串，设置后优先于分项配置 |
| `CATCHHOT_MYSQL_HOST` | `10.25.101.149` | MySQL 主机 |
| `CATCHHOT_MYSQL_PORT` | `3306` | 端口 |
| `CATCHHOT_MYSQL_USER` | `root` | 用户名 |
| `CATCHHOT_MYSQL_PASSWORD` | （见部署配置） | 密码 |
| `CATCHHOT_MYSQL_DATABASE` | `catchhot` | 库名 |

数据迁移 SQL 位于项目根目录：`mysql_schema.sql`（建表）、`mysql_inserts.sql`（历史数据导入）。

### 3.2 多用户共享说明

系统**不区分用户、无登录鉴权**：所有访问者通过前端看到同一份标签、热点与任务数据，且均具备增删改查权限。数据持久化在共享 MySQL 中，多实例后端连接同一库即可协同。

## 4. 已实现功能（M1 + M2 + 评分增强）

### 4.1 标签管理（需求 7.1）✅

- `POST /api/tags` 新增（名称/关键词/平台范围/频率）
- `PUT /api/tags/{id}` 编辑；`DELETE /api/tags/{id}` 逻辑删除（保留历史）
- `POST /api/tags/{id}/toggle` 启停，暂停后立即从调度器移除

### 4.2 多平台抓取（需求 7.2）✅

- 已接入：知乎热榜、B站热搜、GitHub Trending
- 关键词策略：热榜类平台对标题做包含过滤（MVP 策略）
- 单平台故障不影响其他平台；失败指数退避重试 2 次

### 4.3 数据清洗与去重（需求 7.3）✅

- 链接指纹去重：URL 规范化（去跟踪参数/小写/去尾斜杠）后取 SHA1，`UNIQUE(tag_id, fingerprint)` 约束兜底
- 标题相似度去重：difflib ratio ≥ 0.9 视为重复
- 热度归一化：批次内 min-max 映射到 [0,100]；无热度默认 0

### 4.4 热点列表与筛选（需求 7.4）✅

- `GET /api/hot-items`：tag_id / platform / keyword / hours 筛选，time|hot 排序，默认 50 条

### 4.5 趋势分析（需求 7.5）✅

- `GET /api/tags/{id}/trend?days=7|30` 按天聚合数量与热度
- `GET /api/tags/{id}/platform-distribution` 平台分布

### 4.6 任务调度与监控（需求 7.6）✅

- 每标签独立 interval job，频率可配（分钟）
- `GET /api/jobs` 查询执行日志（状态/重试次数/错误信息/抓取与入库数）

### 4.7 复合评分与元信息 ✅

- `HotItem` 新增 `score` 和 `meta` 字段，用于保存多维度综合评分与附加上下文信息
- 评分维度包含：来源/博主权威度、粉丝数、发布时间新鲜度、浏览量、以及归一化热度
- 当前权重采用固定配置，最终输出范围为 $[0, 100]$，便于在列表中直观排序与展示
- 已提供迁移脚本 `scripts/migrate_add_score_meta.py` 与回填脚本 `scripts/backfill_scores.py`，可对历史数据补齐评分

### 4.8 数据重置与重抓管理 ✅

- 新增 `DELETE /api/admin/reset-data`，可清空当前标签的热点历史与任务日志，便于重新抓取验证
- 前端热点页提供“清空并重抓”按钮，支持一键重置与重新触发抓取流程

## 7. 前端页面（M2 前端部分）✅

### 7.1 热点列表 `/hot`

- 顶部筛选栏：标签、平台、时间范围（近 1h/24h/7d/30d）、关键词搜索、时间/热度排序切换
- 表格：平台彩色标签（知乎蓝/B站红/GitHub 灰）、标题外链新窗口打开、摘要两行截断、综合评分徽章与区间着色（≥80 红 / ≥50 橙 / 默认灰）
- 交互：支持按综合评分排序，热点页新增“清空并重抓”按钮，便于重置旧数据并重新抓取
- 分页：20/50/100 条可选

### 7.2 标签管理 `/tags`

- 表格展示标签：名称、关键词、平台范围、抓取频率、运行状态（开关）
- 操作：编辑、暂停/启动、立即抓取（202 手动触发）、删除（二次确认，逻辑删除）
- 新增/编辑对话框：平台多选选项从 `/api/health` 动态读取，新增平台自动出现在选项中

### 7.3 趋势分析 `/trend`

- 默认选中第一个标签，近 7 天/近 30 天切换
- ECharts 组合图：抓取数量折线 + 热度总量柱状（双 Y 轴）
- 平台分布饼图；窗口缩放自动 resize，组件卸载时 dispose 防泄漏

### 7.4 任务日志 `/jobs`

- 标签/状态筛选，展示每次抓取的状态、重试次数、抓取/入库数、耗时、错误信息

### 7.5 前后端联调验证结果

- 四个页面均在浏览器实测通过，无控制台报错
- 数据链路完整：标签创建 → 手动抓取 → 热点列表（含综合评分）→ 趋势图 → 任务日志均可正常展示

## 8. 如何新增一个平台

1. 在 `backend/app/platforms/` 新建 `xxx.py`，继承 `BasePlatform`：

```python
class XxxPlatform(BasePlatform):
    name = "xxx"            # 唯一标识
    display_name = "XX平台"

    async def fetch(self, keyword: str, limit: int = 20) -> list[RawItem]:
        ...  # 返回 RawItem 列表

register(XxxPlatform())     # 文件末尾注册
```

2. 在 `platforms/__init__.py` 追加 `from . import xxx`。

核心流程（调度/去重/存储/API）零改动。标签的 `platforms` 字段使用标识名引用。

## 9. 关键设计说明

- **关键词过滤在适配层**：热榜类平台无搜索接口，先抓全量再按标题过滤。
- **抓取与查询完全解耦**：抓取由调度器线程触发，查询走请求线程，互不阻塞（需求 8.2）。
- **twitterapi.io（Twitter/X）预留**：需要 API Key，拿到后按第 5 节方式新增适配器即可。

## 11. 已知限制

- 热榜过滤策略下，冷门关键词可能长期抓不到内容（将用搜索接口解决）。
- 调度器为内存 JobStore，重启后由 `reload_all()` 从数据库重建（任务不丢失，但错过窗口不补跑）。
- B站热搜接口无热度字段，热度分值为默认值 0。
- 当前复合评分权重仍为硬编码，后续可抽成配置项以满足不同场景。
